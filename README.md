# TraceLens — Image Authenticity Lab

TraceLens is an experimental image-forensics interface for reviewing AI-like visual patterns through a validated model score, original-file metadata, local heuristic signals, and an explainable signal map.

This project focuses on image analysis, explainability, and practical AI-assisted review workflows. It allows users to upload an image, run a detection-style analysis, and review structured feedback such as confidence scoring, visual irregularities, risk indicators, and humanization suggestions.

---

## Overview

**TraceLens** is a web-based image authenticity lab that provides a guided interface for uploading images and reviewing AI-detection signals without presenting them as proof.

The goal of this project is not only to classify an image, but also to help users understand *why* an image may appear AI-generated by presenting visual and textual indicators in a clear, user-friendly way.

## How It Works

1. The user uploads an image.
2. The browser validates basic file size and dimensions.
3. The original file is posted to `api/analyze.php` for authoritative MIME, dimension, EXIF, and format checks.
4. If the server has a Hugging Face token, the backend calls `Organika/sdxl-detector` and strictly validates its `artificial`/`human` response.
5. If model inference is unavailable, the interface clearly falls back to local experimental heuristics.
6. Scores between 0.35 and 0.65 are reported as inconclusive.

## Setup Instructions

### 1. Clone the repository

```bash
git clone https://github.com/tansheetalitaj/ai-image-detector.git
cd ai-image-detector
```

### 2. Install dependencies and create local configuration

```powershell
composer install
Copy-Item .env.example .env
```

Open `.env` and add your Hugging Face token:

```env
HUGGINGFACE_API_TOKEN=hf_your_token_here
```

The `.env` file is loaded automatically and is ignored by Git.

### 3. Run locally with PHP

```bash
php -S localhost:8000
```

Then open:

```bash
http://localhost:8000/ai-image-detector.php
```

## Server-side API token setup

Runtime settings are centralized in `.env`. Copy `.env.example` to `.env`, then
edit the local file. Values already configured in Apache, the operating system,
or a deployment platform take precedence over `.env` values.

```env
HUGGINGFACE_API_TOKEN=your_token_here
```

The real token remains on the PHP server and is never rendered into HTML or sent
to JavaScript. Model settings, decision thresholds, upload limits, timeouts,
application URLs, and the evaluation endpoint can also be changed through
`.env`. See [`docs/CONFIGURATION.md`](docs/CONFIGURATION.md) for the complete
variable reference and deployment precedence rules.

The selected model is `Organika/sdxl-detector`. See [`docs/MODEL.md`](docs/MODEL.md) for its label schema, license, limitations, validation rules, and decision policy.

## Evaluation

The project includes a provenance-first evaluation structure under `evaluation/` and a metric runner:

```bash
php scripts/evaluate.php --endpoint=http://ai-image-detector.local/api/analyze.php
```

It reports precision, recall, false-positive rate, coverage, inconclusive rate, and performance grouped by image type. It refuses to generate metrics from an empty or malformed manifest.

## Security Notes

* Do not commit real API tokens.
* Keep `.env` local; commit only `.env.example` with empty or placeholder values.
* API credentials remain server-side.
* Uploaded images use PHP temporary storage only and are not persisted by the application.
* Use server-side validation for uploaded files.
* Restrict file types and file sizes for image uploads.
* Sanitize user inputs before processing.
